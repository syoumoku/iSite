# 输出契约

## 公开物业搜索与国家报告下载

- `GET /properties/search?q={name}&limit=20` 只搜索 `main_table_ready=true` 的活跃物业，覆盖正式名称和 `property_aliases`；返回正式名、命中名称、命中类型、国家、城市和场景，不做模糊纠错。
- 搜索归一化必须保留中文、阿拉伯文、西里尔文等非拉丁文字的字母身份；仅折叠拉丁文字的重音差异，并清洗大小写、标点和多余空格。
- `GET /outputs/excel/country?country={country}&locale={zh|en}` 只下载发布阶段已生成且审计通过的标准 Excel。导出范围固定为该国完整 `export-ready` 候选池，不继承 UI 城市、场景或详情筛选。
- 报告索引必须同时保存国家数据指纹、内容哈希、Excel 哈希和审计状态。报告缺失、审计失败、文件哈希异常或国家数据指纹过期时返回 `409`，不得返回旧文件或现场生成报告。
- country delta 只重建 changed countries 的中英文标准报告；先上传报告文件，数据库 delta 验证成功后原子切换报告索引。单国报告失败阻断该国版本激活，不影响其他国家现有版本。

## Excel排序规则

- 主表物业点必须按照“年访问量估计（基于Proxy）”从高到低排序；缺失年访问量的物业点排在末尾。
- 主表和各场景分表都必须在“物业点重要证据”右侧输出“主指标量化值”，从当前选中的“物业点重要证据”中提取纯数值，便于 Excel 一键排序；无法提取时留空，不得填入模糊描述。
- 各场景分表物业点必须先按照该场景指标优先级排序，再按照“物业点重要证据”选出的场景主指标数值从高到低排序；缺失或非数值主指标的物业点排在末尾。

## Excel推荐门槛与高亮规则

- 默认使用项目级固定 First Class 推荐门槛：机场年旅客吞吐量 > 2,000,000；会展中心面积 > 25,000 平方米；地铁/交通枢纽换乘线路数 > 1；体育场座位数 > 20,000；商超 GLA > 120,000 平方米；写字楼楼高 > 150 米；酒店房间数 > 150；医院床位数 > 450；大学单一实体校园在校生人数 >= 20,000。
- 大学门槛只接受单一实体校园的在校生总数；大学系统、多校区合计、在线学生总数、年度新生录取数不得直接用于过门槛。无法确认单体校园口径时进入 Review Queue，不自动推荐。
- 推荐筛选阶段所有场景的主指标字段都必须进入智能归一流程：先做规则预识别；存在 Codex OAuth 登录态且未显式关闭时，再用 GPT 将原始字段名/指标名/字段值归一到当前场景允许的 canonical metric key。只有显式设置 provider 为 `gpt/openai` 时才使用 OpenAI API Key。GPT 只能在白名单内选择字段，必须通过置信度校验，且不能改变固定推荐门槛本身。
- 未配置固定 First Class 门槛的场景，按“国家 + 场景”分组，使用当前可用的一级硬主指标排序，取第 10 名的整数主指标值作为回退推荐门槛。
- 没有达到固定门槛、没有量化硬主指标，或仅有模糊角色类证据的物业点不进入推荐清单。
- 主表和各场景分表中达到推荐门槛的物业点必须以浅黄色高亮。
- 主表和各场景分表必须新增“是否被推荐”列；达到推荐门槛的物业点填 `yes`，未达到门槛的物业点留空。
- 主表和各场景分表不得做隔行底色；只有达到推荐门槛的物业点整行使用淡黄色填色。
- 所有推荐物业点必须同步写入“推荐清单”页签。
- “方法说明”页签必须记录推荐门槛规则、推荐清单页签用途和高亮含义。

## 国家看网报告标准输出

- 生成报告前必须先阅读 `docs/15_qa_lessons_learned.md`，将历史问题纳入 Excel/PPT/发件 QA；如本轮发现新问题，先追加到经验库再交付。
- 当用户说“给我 xx 国的看网报告 / 扫网报告 / 输出件”且无另行指定时，默认生成 Excel 与 PPT 的中英双语版。
- Excel/PPT 文档产出后必须先执行输出后审计，再打包或发送。标准入口为 `scripts/generate_standard_country_report.py`；审计入口为 `scripts/qa_standard_report_output_bundle.py`。审计包含规则检查和 Codex OAuth GPT 审计，任何阻断项未清零时不得生成交付 zip 或发送邮件。
- 输出后审计必须至少检查：PPT 一页版场景卡或两页版第 2 页的推荐点指标值与 Excel 推荐清单“门槛指标值”逐条一致；PPT 推荐点不得展示非场景主指标数字；机场/酒店/商超/体育场/会展/办公/医院/交通枢纽等场景不得把面积、年份、距离、会议室面积、URL/ID 等误展示为客流、房间数、座位数或其他主指标。
- Excel 使用本契约的固定页签、排序、推荐门槛、高亮和“推荐清单”规则。
- PPT 默认使用一页精简版，中英文各一份；原两页版保留为用户明确要求详细方法说明/统计页时的可选版本。
- 一页版上部压缩保留标题、候选/推荐/场景 KPI 和四步找楼流程；下部不再把“场景统计”和“优先推荐点”拆成两个区域，而是融合进同一组场景卡。每张卡必须同时展示该场景候选数、推荐数、项目级推荐门槛、代表物业点全称、同口径硬主指标、达标状态和真实物业图片。
- 一页版使用 Imagen 生成的视觉稿作为美化方向，但最终交付必须用原生 PowerPoint 文本、图形、图片和布局对象重建，保证可编辑；不得把整页生成图直接铺成背景后声称可编辑。生成图不得替代真实物业图。
- 一页版目标国家切换时，必须替换标题、KPI、全部场景卡文字、代表物业和图片，不得残留模板示例国家内容；中英文版必须共用同一份候选、推荐和主指标数据。
- 一页版最多展示 9 个场景卡；国家 active/export-ready 场景超过 9 类时，只在 PPT 展示层按项目场景优先级选取前 9 类，完整候选池、全部场景和推荐结果仍必须保留在 Excel，不得因 PPT 容量截断底层数据。图片预检只检查实际进入 PPT 的场景卡。
- 两页详细版第 1 页固定使用“AI工具——找楼逻辑”方法论页，标题不得出现“-iSite/iSite”；去掉中间通栏说明；各场景说明栏必须写清 First Class 推荐门槛，保留分场景指标选择、高亮主指标和四步流程；案例必须换成目标国家真实物业点与真实图片。
- 两页详细版第 2 页只继承当前候选池规模统计页的版式框架，内容必须替换为目标国家相关的场景统计和代表物业点，不展示推荐门槛内容；每个国家统计卡必须同时展示“候选点总数”和“推荐点总数”。
- PPT 的标题、流程、场景卡和统计信息必须使用可读字号；导出前必须渲染检查标题、卡片、表格、国家统计卡、案例说明和页脚不越框。
- PPT 推荐点总数必须与 Excel 推荐清单及主表/场景分表“是否被推荐=yes”的统计口径一致，不能统计未过质量门或未进入推荐清单的点位。
- PPT 与 Excel 的推荐门槛口径必须一致，不能在 PPT 中展示未进入 Excel 推荐清单的推荐点位。
- PPT 与 Excel 中的物业点名称必须显示全称，不使用省略号截断；空间不足时通过换行、缩小字号或减少同格列举数量解决。
- 多国批量报告统一复用 `scripts/generate_standard_country_report.py`，通过重复传入 `--country` 一次生成，不得逐国、逐语言重复启动脚本。标准动作链为：一次加载全批数据并冻结共享 payload -> 一次计算中英文共用的 canonical 推荐结果 -> 一次并发准备代表物业图片 -> 先生成场景数最多的国家并通过确定性冒烟 QA -> 并行生成其余国家的中英文 Excel/PPT -> 全批只调用一次 Codex OAuth GPT 审计 -> 每国打包严格四件套。
- 每国报告必须记录包含数据 payload、输出配置、模板、生成/审计代码和 QA 经验库的内容哈希。哈希未变化、上一版规则审计与 GPT 审计均通过且四件套完整时，直接复用已审计成品；任一输入变化时自动失效并重新生成。图片下载、格式归一和双语 PPT 必须共享同一缓存结果。
- 批量命令示例：`PYTHONPATH=src .venv/bin/python scripts/generate_standard_country_report.py --country Pakistan --country Uzbekistan --country Kazakhstan --country Georgia --max-workers 4`。默认保留阶段级 JSON 计时，至少包括 payload、复用检查、图片准备、冒烟、并行生成和批量审计。

- 发送看网报告、扫网报告、标准输出件或报告附件时，除非用户明确指定不抄送，默认固定抄送：`Steve.zengchuxian@huawei.com`、`liaozhaomu@huawei.com`、`zhangming.dis@huawei.com`、`luojiangtao@huawei.com`。
- 如果用户使用姓名短写，按项目内已沉淀别名解析：`zengchuxian` -> `Steve.zengchuxian@huawei.com`，`liaozhaomu` -> `liaozhaomu@huawei.com`。
- 发件日志不得记录 SMTP 授权码、密码或任何敏感认证信息。
