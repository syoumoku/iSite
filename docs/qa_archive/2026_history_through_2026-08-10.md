# QA Lessons Learned

本文件沉淀 iSite2 扫网、证据补足、Excel/PPT 输出、邮件交付和 UI QA 中已经暴露的问题。每次 QA 检查、扫网收尾、输出件生成或发件前，必须先阅读本文件，并把其中相关经验纳入检查清单。

## 使用规则

1. QA 开始前先读本文件，再读当前任务的输入、输出和日志。
2. QA 发现新问题后，先补一条经验记录，再结束本轮任务。
3. 每条记录必须说明问题表现、根因、固化防线和下次 QA 必查项。
4. 重复出现的问题优先固化到配置、脚本、测试或输出模板中，不只停留在人工提醒。
5. Review Queue 的动作必须可执行，不能写“待研究”或“后续核验”这类空泛描述。

## QA 快速前置清单

- 主指标必须是分场景一级硬指标。机场客流、体育场座位数、会展面积、商超 GLA、酒店房间数、医院床位数、交通枢纽线路数等优先；`gateway_role`、`hub_role`、`landmark role` 只能做辅助描述。
- 数值解析必须检查单位和上下文。不要把年份、Wikidata 属性编号、线路名、面积数值解析成客流、床位、房间、线路数或座位数。
- Direct 主指标字段只能承载一个 canonical 口径。页面同时出现客房数、会议面积、年客流、终端处理能力等多个数字时，主指标字段只写当前场景主指标，其他数字进入 secondary/context/proxy，不得混写在同一个 `field_value`。
- 推荐筛选必须通过智能指标归一。规则预识别后，存在 Codex OAuth 登录态且未显式关闭时，用 GPT 将字段名和值归一到场景白名单内的 canonical metric key。
- Excel 主表按预计年访问量排序，场景分表按场景主指标排序；推荐点必须同步出现在主表、场景分表和推荐清单中。
- Excel 主表和各场景分表都必须在“物业点重要证据/Core Objective Evidence”右侧有“主指标量化值/Primary Metric Value”，从当前选中的场景主指标证据中提取数值；无法提取时留空，不能把描述、年份或非主指标数字塞进去。
- Excel 只给推荐点填浅黄色，不做隔行底色；“是否被推荐”列中推荐点填 `yes`，非推荐点留空。
- PPT 推荐点总数必须与 Excel 推荐清单和“是否被推荐=yes”行完全同口径。
- PPT 和 Excel 中物业点名称必须显示全称，不使用省略号。
- Excel/PPT 文档产出后必须运行输出后审计：先跑规则脚本校验 PPT 一页版场景卡或两页版第二页推荐指标值与 Excel 推荐清单一致，再由 Codex OAuth GPT 审计摘要和历史 QA 经验；审计失败不得打包、发送或对外交付。
- 输出层不得直接取 `evidence[0]` 当主要证据，必须选择当前场景最强、最硬、最可量化的证据。
- 推荐理由优先复用 UI 同源的 `conclusion.reason_to_recommend`，输出层不得生成空泛理由覆盖已有好理由。
- 图片必须是真实物业图片，并通过本地代理/缓存可打开。缺图或坏图要补图或清空图片字段，不能放入破图。
- 批量图片搜索不能只凭图片可打开或弱关键词命中入库；图片来源页面必须与目标物业、城市/国家、场景实体同向一致，泛图、异地同名、目录页相邻图、非目标国家案例页必须清空，不得进入 active/export。
- 每个国家扫网/补证前必须有国家本地化搜索 profile：官方语言、实际搜索语言、主要搜索引擎/搜索渠道、本地域名和场景主指标本地术语；QA 必查是否先用官方语言搜索本地来源，英文只能作为兜底或交叉验证。
- Firecrawl 先 search 留存结果和目录 manifest，再 scrape 少量高质量页面；不得出现 credit 已消耗但搜索结果未留存。
- 免费结构化源先行；需要网页搜索/抓取时默认使用本地部署 Firecrawl，并可用本地 SearXNG 做搜索兜底。云端 Firecrawl 必须显式选择且默认禁用；QA 必查 search/scrape manifest 是否留存 `language/search_channel/query/title/url/snippet/adopted/skipped_reason/target_scene`，并确认本地调用的云端 credits 为 0。
- 自动化 Firecrawl 固定使用 `scripts/run_firecrawl_cli.py` 包装入口，不裸跑 `firecrawl ...`。
- 扫网默认新机会点优先，必须使用已知物业索引、URL 去重和 identity-key upsert，避免多轮重复获取同一物业。
- overlay 中质量门通过的候选必须同步入 active；疑似重复进入 Review Queue，不自动合并。
- GPT 相关默认使用 Codex OAuth。只有用户明确要求 API Key 通道时，才显式切换到 `gpt/openai` provider。
- 本地化缓存命中必须同时满足 key 命中和结果可用：`skipped_no_provider`、空译文、跨语言原译文相同且含可翻译文本的记录都按缺口处理；发布门禁必须扫描本轮实际引用的全部文本 hash。
- 邮件交付前检查文件存在、Office zip 结构可打开、附件数量、收件人/抄送和发送日志；扫网/看网报告类输出件默认固定抄送 `Steve.zengchuxian@huawei.com`、`liaozhaomu@huawei.com`、`zhangming.dis@huawei.com`、`luojiangtao@huawei.com`，除非用户明确要求不抄送；不得把 SMTP 授权码写入输出或日志正文。
